# WebDAV Downloader

Go-приложение рекурсивно скачивает файлы с WebDAV-сервера, сверяя уже сохраненные файлы и создаёт HTML-отчёт.

## Запуск локально

Требуется Go 1.22 или новее. Внешних зависимостей нет.

Скопируйте `.env.example` в `.env`, укажите параметры сервера и запустите:

```sh
make run
```

Или соберите исполняемый файл:

```sh
make build
./bin/yandex_disk_saver
```

Остановка по Ctrl+C или SIGTERM: приложение дожидается активных загрузок.

### Запуск через docker-compose

Образ запускает [supercronic](https://github.com/aptible/supercronic), который по расписанию из `/etc/crontab` вызывает `/app/yandex_disk_saver`. Расписание по умолчанию — понедельник, 03:00 (файл `crontab` в репозитории).

```sh
cp .env.example .env   # укажите параметры WebDAV
docker compose up -d
```

- Переменные берутся из `.env`; `DESTINATION_DIR` в compose-файле принудительно задан как `/vault`.
- Файлы сохраняются в `./downloads` на хосте (том `./downloads:/vault`).
- Чтобы изменить расписание, отредактируйте `crontab`, раскомментируйте в `docker-compose.yml` строку `./crontab:/etc/crontab:ro` и перезапустите контейнер: `docker compose up -d --force-recreate`.
- Логи: `docker compose logs -f`.

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `WEBDAV_PROTOCOL` | `http` | `http` или `https` |
| `WEBDAV_HOST` | `localhost` | Имя хоста или IP-адрес, без порта |
| `WEBDAV_PORT` | `80` | Порт WebDAV |
| `WEBDAV_USERNAME` | `user` | Логин |
| `WEBDAV_PASSWORD` | `password` | Пароль |
| `WEBDAV_REMOTE_PATH` | `/` | Начальный удалённый каталог |
| `DESTINATION_DIR` | `./downloads` | Папка для файлов и отчёта |
| `MAX_CPUS` | `2` | Число ядер CPU (`GOMAXPROCS`), `0` — без ограничения |
| `MEMORY_LIMIT_MB` | `256` | Мягкий лимит памяти в МБ (`GOMEMLIMIT`), `0` — без ограничения |
| `MAX_FILE_RETRIES` | `2` | Максимальное число попыток скачивания одного файла (включая первую) |
| `DIRECTORY_RETRIES` | `5` | Сколько раз повторить запрос каталога после ошибки; перед каждым повтором проверяется клиент и при необходимости пересоздаётся. Если каталог получить не удалось, он помечается `error` (красным в отчёте), а файлы в нём не удаляются из диска |
| `REPLACE_WARN_PERCENT` | `10` | Если суммарный размер файлов на сервере, требующих замены (не совпал ETag), больше этого процента размера всех файлов сервера, замена не выполняется и создаётся `REPLACE_WARN.md` |
| `DELETE_WARN_PERCENT` | `10` | Если суммарный размер файлов, которых нет на сервере, больше этого процента размера локального хранилища, они не перемещаются в `.trash`, а создаётся `DELETE_WARN.md` |
| `TRASH_RETENTION_DAYS` | `180` | Через сколько дней файлы из `.trash` удаляются окончательно (`0` — сразу) |

Порядок работы при каждом запуске:

1. Полностью строится дерево WebDAV; при ошибке сканирования дальнейшие шаги не выполняются.
2. Строится дерево файловой системы.
3. Файлы, совпавшие по MD5 с ETag, получают `completed`.
4. Для оставшихся `pending` файлов, отсутствующих на диске, ищется локальный файл с тем же MD5 — он копируется на нужное место (исходный не удаляется).
5. Сначала считается суммарный размер всех файлов с несовпавшим ETag; если он превышает `REPLACE_WARN_PERCENT`, ни один из них не заменяется и создаётся `REPLACE_WARN.md`. Иначе файлы заменяются по одному, затем докачиваются недостающие. Скачивание идёт в `<файл>.tmp`; после проверки MD5 оригинал удаляется и tmp переименовывается. При любой ошибке tmp удаляется.
6. Файлы, которых нет на сервере, перемещаются в `.trash` (см. `DELETE_WARN_PERCENT`); список — в `.trash/TRASH.md`.
7. Из `.trash` окончательно удаляются файлы, удалённые `TRASH_RETENTION_DAYS` дней назад и ранее.

Служебные файлы в корне папки назначения: `download-report-yyyyMMdd.html`, `REPLACE_WARN.md`, `DELETE_WARN.md`, `DOWNLOAD_ERROR.md`, `.trash/`; они не участвуют в сравнении.

Ошибки скачивания (в том числе несовпадение MD5) переводят файл в статус `error` и обрабатываются отдельной очередью с повторами. Если все попытки исчерпаны, файл добавляется в таблицу `DOWNLOAD_ERROR.md` в корне папки назначения (путь, дата, размер в МБ, код ошибки: HTTP-статус, `MD5` или `ERR`).

Файл `download-report-yyyyMMdd.html` (суффикс — текущая дата) в папке назначения обновляется раз в 30 секунд и сохраняется в последний раз по окончании цикла работы, после чего программа завершается. В отчёте отображаются папки до второго уровня, общий размер и процент завершённых файлов; папки с ошибками выделяются красным, полностью скачанные — зелёным.
